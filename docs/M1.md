# M1 Generator

Done on 2026-11-07: the plan in #19, then four stacked PRs, #20–#23. M1 added `RoadGenerator`, an endless N/W staircase of junctions whose expected exits alternate left and right, with dead ends on the wrong exits; `RoadBuffer`, the tiles around the car; the five areas and their schedule; `Iso`; and a grey-box road drawn from the road's geometry, shown by a road viewer until M2. Its changes to IP §4 M1, marked **Δ**, were never folded into IP (Q8). The full plan, with its verification, negative cases and review history: `git show 08f316f:M1_PLAN.md`.

## 1. Goal and exit criteria

Goal (IP §3): `RoadGenerator` meets every unit invariant in `plan.md` §11, and the grey-box road is visible and scrollable. **Δ G4:** the viewer was the main scene until M2.

E1–E10 covered the generator's rules, the buffer, the area switches, the atlas and the renderer, the smoke run, the Web and Fold4 checks (E9), and green checks. All were met but E9's Fold4 part (§7).

## 2. Findings

- **G1.** IP M1.2's "weak ref" `junction: RoadTile` is a strong reference: with the junction's `branches`, it makes a `RefCounted` cycle that leaks while GUT passes. Fix: `RoadTile.junction_index`, for `RoadBuffer.path_tile()`, and a leak guard (§5.9).
- **G2.** `TileMapLayer`'s DIAMOND_DOWN cells centre half a tile right of `Iso.tile_to_world()`. Fix: `Iso.layer_offset()`, (−64, 0) for the road layer and (−16, 0) for the ground.
- **G3.** IP M1.3 checked a double claim with `assert`. Release builds strip it, and a debug run prints `SCRIPT ERROR: Assertion failed`, abandons the calling function and still exits 0. Fix: `OccupancyGrid.claim(tile) -> bool` calls `push_error`, returns false and keeps the old tile; `release(tile)` frees the cell only if `tile` holds it. The test uses `assert_push_error`.
- **G4.** IP M1.6's `tools/debug_road.tscn` is never exported (docs/M0.md F13) or smoke-tested. Fix: the viewer is `ui/main.tscn` (Q1).
- **G5.** M1 needs M4's `AreaDef` and `AreaSchedule`. Fix: the subset it uses (§5.6), with `set_piece: StringName`, as M4.4's scenes didn't exist; `AreaScheduleEntry` has its own file, as a `.tres` resource needs.
- **G6.** IP M1.5 emits on `EventBus`, which comes in M2.7. Fix: `RoadBuffer`'s own signals (Q6).
- **G7.** Props need `PropDef` (M4.1), `PropPool` (M5.2) and art. Fix: none in M1 (Q2); `hash("%d:props" % run_seed)` is reserved for them, so props can't change a road.
- **G8.** A hand-drawn grey box could drift from the D4 capsules that decide off-road. Fix: `GreyboxAtlas` draws it from `RoadGeometry`, and a test compares the pixels.
- **G9.** IP M1.4's fallbacks for a blocked dead end can never trigger (§5.4). Left out; the tests require `dropped_count == 0`.
- **G10.** Hairline seams at zoom 0.5. Fix: `GreyboxAtlas.BLEED_PX`, 1 px.
- **G11.** The car would start on a junction. Fix: `Tuning.START_STRAIGHT_TILES`, 4 (Q4).
- **G12.** The generator never emits `CORNER`, as every turn is a junction. The value stays; M5.1 needed no corner art.
- **G13.** IP M1.4's `_init(seed: int, …)` shadows the built-in `seed()`: the editor warns SHADOWED_GLOBAL_IDENTIFIER, but CI stays green. Fix: `run_seed`; M2.7's `start_run(seed := -1)` became `GameState.start_run(p_run_seed)`.
- **G14.** IP doesn't say when a schedule entry applies: §5.6 does.
- **G15.** IP doesn't define lookahead: §5.5 does.
- **G16.** Under xvfb without `--audio-driver Dummy`, Godot prints `ERROR: Condition "status < 0" is true. Returning: ERR_CANT_OPEN` and still exits 0. A screenshot script that jumps along the path skips the junctions that the scene counts. Fix: pass the flag, and drive (§6.3).
- **G17.** `smoke.sh` needs the `autopilot: tile N, turns N, area <id>` line that `ui/main.gd` prints when it quits with `--autopilot`. A new main scene keeps the line, or changes `smoke.sh` in the same PR (§5.9).

## 5. Design

### 5.1 Files

IP §2's layout, plus `areas/area_schedule_entry.gd` (G5). `tests/helpers/road_fixtures.gd` has no `class_name`, as `tests/` isn't exported.

### 5.2 Road types

- `Heading` (static): `N, E, S, W`, `VEC` (N is −y, W is −x), `left()`, `right()`, `opposite()`, and `turn_for(turn_number, h)`, left on even turns.
- `RoadTile` (`RefCounted`): `Type` is `STRAIGHT`, `CORNER`, `T_JUNCTION`, `CROSS_JUNCTION`, `DEAD_END` or `SET_PIECE`; −1 and `&""` mean unset. It holds strong references only to its own dead ends, `branches` (G1).
- `OccupancyGrid`: at most one tile per cell, with `claim()` and `release()` (G3).
- `RoadGeometry` (static, D4): a point is on the road within `Tuning.ROAD_HALF_WIDTH` of a segment from `CENTRE` to an exit's `EDGE_MID`.

### 5.3 Generator

`RoadGenerator.new(run_seed, schedule)`. `next_tile()` returns the next correct-path tile, claimed in `occupancy`: a pending set piece's, else the current straight's (the first has 4), else a junction with its dead ends in `branches`.

- `_init` reports a missing or broken schedule with `push_error("AreaSchedule: " + problem)`, then uses one default area, `fallback`. It seeds the road stream with `hash("%d:road" % run_seed)` (D8).
- A junction's expected exit is `Heading.turn_for(turn_count, heading)`. Its wrong exits are the opposite turn, and straight on (a `CROSS_JUNCTION`) if `randf() < cross_junction_chance`. Each gets a dead end of `randi_range(2, 3)` tiles, else 1 (`shortened_count`), else none (`dropped_count`). Dead-end tiles carry `junction_index` and `branch_exit`; the last is a cap.
- **RNG order** per junction: the crossroads `randf()`, one `randi_range()` per wrong exit (the opposite turn first), then the next straight. A new order changes every seed's road (D8).
- Since: the junction kinds come from the same `randf()` (docs/ROADGEN.md R3); dead ends are 6–9 tiles (R4) and stop before a taken cell (R5); and `p_tutorial` adds the tutorial's road (docs/TUTORIAL.md §5.1).

### 5.4 Why dead ends never block the path

The path heads N, then turns L, R, L…, so it moves only towards −x and −y, in straights of at least 2 tiles (D7). At a junction at (x, y) entered heading N, earlier path cells lie below row y and later ones left of column x, so its E and N dead ends never touch the path; heading W is the mirror image. Only the straight-on dead end of the junction two turns earlier can meet them, at column x + 3 or beyond, so a 1-tile stub always fits and nothing is dropped (G9).

### 5.5 Buffer

`RoadBuffer` owns the `generator` and the correct-path tiles around the car.

- `tiles_generated(tiles)` lists each new path tile, then its dead ends; `tiles_freed(tiles)` comes after their cells are released (G6).
- `start()` generates path indices 0–50. `on_car_path_index(i)` ignores an `i` at or below the car's. When lookahead, `last_index() − car_index()` (G15), is below 25, it generates to `i + 50`. It frees path tiles below `i − 5`, with their dead ends.
- `path_tile(i)` is null outside the buffer; `tile_at(cell)` finds dead ends too; `centreline_point()` clamps to the buffer's ends.
- Since: 55 ahead, refill at 37 and 20 behind (docs/M5.md L2, docs/ROADGEN.md R6).

### 5.6 Areas and the schedule

Only the subset M1 uses (G5); M2.2 and M4.1 added fields.

- `AreaDef`: `id`, `display_name`, `id_color`, `min_straight`, `max_straight` and `cross_junction_chance`. `AreaScheduleEntry`: `turn`, `area`, `set_piece: StringName` and `set_piece_length`. `validate()` returns their problems, such as `min_straight < 2` (D7), or turns that don't start at 0 and strictly increase.
- The five areas take IP M4.2's values. `schedule.tres`: city at turn 0; rural at 34, after a 6-tile `tunnel`; meadows at 100, after a 5-tile `bridge`; village at 200; desert at 220, for ever.
- **Turn semantics (G14).** An entry for turn T applies once T junctions exist. That last junction and the set-piece tiles keep the old area; the next straight is the new area's.

### 5.7 Grey box

- `Iso` (static): `TILE_W` 128, `TILE_H` 64 and `GROUND_PER_TILE` 4, with `tile_to_world()`, its inverse `world_to_tile()`, and `layer_offset()` (G2).
- `GreyboxAtlas` (static, G8): a road column per `exits − 1`, for all 15 road tiles, and the rows `ROAD`, `DEAD_END` (the debug tint), `TUNNEL` and `BRIDGE`, drawn once from `RoadGeometry.distance_to_centreline()`. The ground is a two-shade checker of each area's `id_color`.
- `WorldRenderer` (`world/world.tscn`) drew a road cell and 4×4 ground cells for each of the buffer's tiles.
- Since: M3 split `build(schedule)` from `bind(buffer)`, so that a retry keeps the tilesets (docs/M3.md J11, J12), and M5 gave each area its own art in the atlas's layout (docs/M5.md §5.5).

### 5.8 Road viewer

`ui/main.gd` moved a ghost along `buffer.centreline_point()`, called `buffer.on_car_path_index()` every physics frame, and printed `grey box: tilesets built in %d ms` and, with `--autopilot`, the `autopilot:` line (G17). The Web build has no system font, so its "↑" showed as a box. M2 (#28) replaced it with the game, which keeps both lines and `test_smoke.gd`'s glyph test.

### 5.9 CI scripts

- `run_tests.sh` (G1) fails on `ObjectDB instances? (was|were) leaked|resources? still in use at exit`.
- `smoke.sh` (G17) runs `-- --autopilot --seed=12345`, and fails without a line matching `^autopilot: tile [1-9]`. The tile is the buffer's car index, so a scene that stops driving reports 0. The rest isn't pinned: any change to the road, the areas or the driving changes it.

### 5.10 Tuning

`config/tuning.gd`: `ROAD_HALF_WIDTH` 0.32 (D4); `BUFFER_AHEAD` 50, `BUFFER_REFILL_AT` 25 and `BUFFER_BEHIND` 5; `START_STRAIGHT_TILES` 4; `DEAD_END_MIN_TILES` 2 and `DEAD_END_MAX_TILES` 3. The buffer and the dead ends have changed since (§5.3, §5.5).

### 5.11 Tests

A unit test file per class. The occupancy test covers 200 seeds × 500 turns, and the buffer's fuzz 20 seeds × 400 car moves, backwards included. The determinism tests compare `road_fixtures.signature()`.

## 6. Verification

The five checks passed on every PR, locally and in CI, and 28 negative cases showed that the tests catch what they guard. PR 4's head: 29 scripts, 52 tests and 143,469 asserts; `smoke.sh` printed `autopilot: tile 1440, turns 247, area desert`.

### 6.3 Screenshots

A scratch `SceneTree` script drove the viewer fast with seed 12345, and saved the viewport's image 2 tiles before each area and set piece:

```bash
xvfb-run -a -s "-screen 0 1280x1024x24" godot --path . --rendering-driver opengl3 \
  --resolution 360x640 --audio-driver Dummy --fixed-fps 60 -s res://shot_drive.gd -- --seed=12345
```

It read private fields, so it wasn't committed; IP M7.6's `tools/screenshots.gd` (M6.6 then) is to be the real tool. Without `--audio-driver Dummy`, Godot prints an `ERR_CANT_OPEN` error (G16).
