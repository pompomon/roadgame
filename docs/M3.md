# M3 Failure

Done: the plan PR #30 and the stacked PRs #31–#33, merged on 2026-11-09. A wrong or missed turn ends the run at once; the car stops, a disaster from the area's pool plays, and then game over shows the cause and the stats. A crash smokes and shakes instead, and Retry starts the next run in place. M5 later brought the wreck frame and the Title button, and M6 PR 8 (#53) retired the sinkhole. The full plan, with its verification, negative cases and review history: `git show 08f316f:M3_PLAN.md`.

## 1. Goal and exit criteria

Goal (IP §3): "Wrong or missed turn → Sinkhole → game over → retry; crash path works". The run still ends at once, as in M2, but game over waits while the end plays. Each exit criterion, E1–E14, had its tests, except E14, the green checks, and one manual check:
- **E13.** On the Web build in Chrome and Firefox, and the debug APK on the Galaxy Z Fold4: a wrong turn plays its disaster and then game over, a crash smokes and then game over, Retry works by tap, click and Enter, and no errors show in the console or `adb logcat` (§7).

## 2. Findings

Each fix replaces IP §4 M3 where they differ.

- **J1.** IP called `end_run()` only after the disaster, so the game stayed `RUNNING`, and pausable, while it played. `main.gd` ends the run at the turn or the crash, with `CarSim`'s cause; the director then plays the end in `DISASTER` or `CRASH`, where nothing pauses, and game over comes when it ends (§5.2).
- **J2.** Tweens and timers don't move in GUT's `simulate()` (`addons/gut/gut_to_move.gd:62–92`). Every M3 timing counts `_physics_process` deltas.
- **J3.** `CarController` sets the car's position from `CarSim` every physics frame, which undid IP's tween. A disaster may change only the car's `scale` and `modulate` (and `rotation` since docs/M4.md K19).
- **J4.** Once the run was over, M2's car braked at `BRAKE`, rolling 6.1 tiles in 1.75 s from the cap. `CarSim.step()` brakes at `max(BRAKE, speed / STOP_SECONDS)`, worked out at the first step after the end, straight along its heading without steering, so the car stops within `STOP_SECONDS` of the step that ended the run.
- **J5.** `plan.md` §7.1 and IP §5.2 put `DisasterLayer` under `Main`, over the car it swallows. It is `World/DisasterLayer`, between `RoadLayer` and `Props`: disasters draw above the road and below the car and the props.
- **J6.** `AreaDef` had no `disasters` until IP M4.1. M3 adds `AreaDef.disasters: Array[PackedScene]`, with the sinkhole in every pool until M4.5, so a wrong turn in any area ends in a disaster. An empty pool is an error that ends the sequence.
- **J7.** `SaveService.record_disaster()` came in M5.4; each disaster has an `id` for it.
- **J8.** The Title button waited for M5.5; M3 had only Retry.
- **J9.** M2's HUD retried on any tap or Enter. Only the game-over screen's Retry retries (§5.8).
- **J10.** The HUD reset only in `_ready()`, as M2 reloaded the scene; `Hud._reset()` now runs on every `run_started` too.
- **J11.** `WorldRenderer.bind(buffer, schedule)` built the tilesets and followed one buffer, once. `build(schedule)` makes the tilesets once; `bind(buffer)` drops the last buffer, clears the layers and draws the new one.
- **J12.** Rebuilding `World` on retry would rebuild its tilesets: 59–63 ms headless, 100–390 ms in browsers. Retry keeps `World`; the road, the car and its `CarSim` are new.
- **J13.** `queue_free()` left two cars under `Props` for a frame. Retry frees the car, and `DisasterDirector.clear()` the disaster, with `free()` at once; `test_retry.gd` checks it with `assert_no_new_orphans()` and `is_instance_valid()`.
- **J14.** `DisasterParams.seed` would shadow `seed()`; it is `particle_seed`.
- **J15.** The grey box needed no hole shader or clip mask: the hole grew by its scale, and the car shrank and darkened.
- **J16.** IP used `GPUParticles2D`. The debris and the crash smoke are `CPUParticles2D`, like M2's dust, so no particle shader compiles at the first disaster. Godot gives each `CPUParticles2D` a random seed when it's made (`scene/2d/cpu_particles_2d.cpp:1733` in 4.7.2), so each needs `use_fixed_seed` and a nonzero seed: the editor doesn't save 0, the declared default (`:1553`), so the random seed would stay. A disaster's particles take its `particle_seed`; the smoke has `seed = 1` in `car/car.tscn`, so every crash smokes alike.
- **J17.** The stream can't know where the car stops. `DisasterParams.roll(rng, origin)` draws five values in a fixed order and takes `origin_world` from the stopped car.
- **J18.** A forced `--seed` stays for every retry (docs/M2.md H28); otherwise each run gets a new random seed.
- **J19.** The game-over screen shows the seed in debug builds only: `show_seed := OS.is_debug_build()`, which tests change. The HUD's seed line stays in every build (Q6).
- **J20.** IP's 2–4 s had no start. It runs from the wrong or missed turn to game over, the stop and the delay included: 2.5–3.5 s for the sinkhole, plus a frame or two for rounding (P10). `DISASTER_TIMEOUT` counts from the turn too.
- **J21.** The disaster stream is seeded with `hash("%d:disaster" % run_seed)`, like the road's with `"%d:road"`: one stream per run.
- **J22.** No crash art before M5.1: the crashed arrow turned grey (`CRASH_TINT`) through `self_modulate`, and smoked.
- **J23.** IP's "turn 3" is the third junction: `turn_number` 2.
- **J24.** No signal carries the car and the camera, so `main.gd` calls `play_disaster(area, car, camera)` and `play_crash(car, camera)`.
- **J25.** `DisasterBase.finished` has `@warning_ignore("unused_signal")`, as only the disasters emit it.
- **J26.** `@abstract` doesn't stop `DisasterBase.new()`, so the director checks each scene's root.

## 5. Design

### 5.1 Files

New: `disasters/disaster_params.gd`, `disaster_base.gd` and `disaster_director.gd`, the sinkhole, and `ui/game_over.tscn`. Changed: `config/tuning.gd`, `areas/`, `car/`, `world/` and `ui/`. `GameState` kept M2's states and transitions.

### 5.2 The end of a run

`main.gd`'s `_end_run(cause)` records the distance, turns the input off and calls `GameState.end_run(cause)`, so `run_ended` fires once (J1). Then `main.gd` calls the director's `play_disaster()` with the junction's area, or `play_crash()`, and shows game over on `sequence_finished`. `_start_run(run_seed)` builds every run, the first and each retry, and `_ready()` builds the tilesets once, so a session prints one `grey box:` line. `_retry()`, allowed only in `GAME_OVER`, closes the screen, clears the director, stops the shake and frees the car (J13).

### 5.3 Pools, params and the disaster stream

`DisasterParams` has `direction` (a unit vector in tile space), `intensity`, `delay` (from `play()` until the disaster shows), `particle_scale`, `particle_seed` and `origin_world`. `DisasterDirector.start_run(run_seed)` makes the run's stream with `stream(run_seed)` (J21). The director draws the scene with `pick()`, one `randi_range()`; then `roll()` draws all five values, whichever the disaster reads, so the draws don't depend on the disaster (J17).

### 5.4 The director

`DisasterDirector` steps `enum Sequence { NONE, STOPPING, PLAYING, CRASH, FINISHED }`. After a wrong or missed turn it waits in `STOPPING` until the car's speed is 0; then it picks a scene from the area's pool, adds it to `World/DisasterLayer` with its `car` and `camera`, rolls the params at the car and calls `play(params)`. A crash shakes the camera by `CRASH_SHAKE` and waits `CRASH_SECONDS`. `FINISHED` emits `sequence_finished` once per run; at `DISASTER_TIMEOUT` the director reports `push_error()` and finishes anyway. A second sequence, an empty pool or a root that isn't a `DisasterBase` is an error.

### 5.5 Disasters and the sinkhole

`DisasterBase` is an `@abstract` `Node2D` with `signal finished`, an `id`, `car`, `camera` and `play(params)`. Its doc comment states the contract: `play()` comes once, after the stop; `finished` comes once, 2–4 s after the turn (J20); the disaster times itself by physics deltas (J2), changes only the car's `scale` and `modulate` (J3), and works without a car or a camera. The sinkhole was two ellipses grown only by `scale`, which doesn't redraw a `Polygon2D`, and 40 debris particles. After its delay it opened for 0.8 s, sank and faded the car for 1.0 s, held 0.6 s and finished.

### 5.6 The car's stop and crash

From M2's cap of 7 tiles/s the stop brakes at 11.7 tiles/s² and takes 2.1 tiles (J4). Wrong and missed turns come at about `junction_speed`, 2.0 tiles/s, so the car stops at `BRAKE` in about 0.5 s and 0.5 tiles, inside the exit it took. On a crash, `CarController` shows the wreck and starts `%Smoke`, 20 black puffs at 0.8 alpha from a fixed seed (J16).

### 5.7 Camera shake

`CameraRig.shake(intensity, seconds)` replaces any shake still going, and `stop_shake()` ends it. It moves only `offset`, by `(sin(t·SHAKE_FREQ_X), cos(t·SHAKE_FREQ_Y)) × SHAKE_PX × intensity × (1 − t / seconds) / zoom`: the same size on screen at every zoom, fading out, with no randomness.

### 5.8 Game over and the HUD

`GameOver` is hidden until `open(stats, area)`; M6 added `fate`. A `Shade`, black at 55 %, stops taps. `END_MESSAGES` moved there from the HUD; an unknown cause shows `FALLBACK_MESSAGE`, "Game over", with an error. `open()` gives Retry the focus, so Enter and Space press it; `close()` hides the screen and so releases the focus; and `retry_requested` fires only while the screen is visible (J9).

### 5.9 Tuning

Unchanged at 08f316f: `STOP_SECONDS` 0.6 s, `CRASH_SECONDS` 1.2 s, `DISASTER_TIMEOUT` 6.0 s, delays 0.1–0.5 s, intensities 0.5–1.0, particle scales 0.75–1.25, `SHAKE_PX` 6.0 screen px, `SHAKE_FREQ_X` and `_Y` 47.0 and 31.0 rad/s, and `CRASH_SHAKE` 0.5 for `CRASH_SHAKE_SECONDS` 0.4 s. `CRASH_TINT` and the `SINKHOLE_*` values are gone.

### 5.10 World

`World` draws its children in order and only `Props` sorts by y, so `DisasterLayer` goes between `RoadLayer` and `Props` (J5). The debris and the smoke have `z_index` 1, so they draw in front of the car. The order is now `Ground`, `SetPieces`, `RoadLayer`, `Skids`, `Shadows`, `DisasterLayer`, `Props`, `Lamps`.

### 5.11 Tests

GUT went from 147 tests to 201. The integration tests run the main scene in a 360×640 `SubViewport` with `tests/helpers/main_scene.gd`; `wrong_turn_pilot.gd` takes a wrong exit at the third junction (J23).

## 6. Verification

Each PR passed the five local checks and CI, with 60 negative cases and 10 probes. At #33's head: 66 scripts, 201 tests and 144,632 asserts, and `smoke.sh` still printed `autopilot: tile 165, turns 35, area rural`. The Web build ran its ends and retries in Chrome and Firefox with no errors.

- **P10.** A wrong turn's end with the longest delay, 0.5 s, took 3.52 s from the cap with `STOP_SECONDS` at 0.6 s, 3.98 s at 1.05 s and 4.02 s at 1.1 s; from `junction_speed`, where the stop is at `BRAKE`, 3.43 s at each. Each is a frame or two more than the stop, the delay and the phases added up: the stop and the disaster's clock each sum steps of 1/60 s, and a clock that sums them can fall just short of its time and so end a frame late (30 steps sum to just under 0.5 s). So time-bound tests add one `DELTA` per clock: `test_disasters.gd` keeps the slowest end, plus `STOP_SECONDS` and `2 * DELTA`, within 4 s. With the sinkhole, `STOP_SECONDS` could grow to 1.05 s.
